# Экзаменационное задание: Employee Management API на .NET 10


Студент за один день пишет REST API для системы управления сотрудниками на ASP.NET Core Web API по принципам Clean Architecture с доступом к данным через Dapper. Работа показывает, умеет ли он собрать рабочий backend от схемы БД до Swagger.

## Описание задания

| Параметр | Значение |
| --- | --- |
| Время на выполнение | 1 день, включая тестирование и сдачу |
| Платформа | .NET 10 или новее, ASP.NET Core Web API |
| База данных | PostgreSQL (локально или в Docker); скрипт создания таблиц выдаётся |
| Работа | индивидуальная |
| Разрешено | официальная документация, свои конспекты, NuGet-пакеты из списка требований |

Что проверяется: асинхронность, Dapper, Swagger, Web API, Clean Architecture, логирование, middleware и DTO. Подробные требования — в разделе «Технические требования».

## Предметная область

Нужно сделать backend «Employee Management System» для HR-отдела компании: справочники отделов и должностей, карточки сотрудников и заявки на отпуск с согласованием.

HR-менеджер должен уметь:

- вести справочники отделов и должностей;
- принимать сотрудников на работу, редактировать их данные и увольнять;
- искать сотрудников по имени, отделу и должности с постраничным выводом;
- принимать заявки на отпуск и больничный, согласовывать или отклонять их.

## Модели (сущности Domain)

В решении должно быть 4 модели: Department, Position, Employee, LeaveRequest. Связи: один отдел — много сотрудников, одна должность — много сотрудников, один сотрудник — много заявок на отпуск. Все даты в коде — тип DateTime.

### Department — отдел

| Поле | Тип | Ограничения |
| --- | --- | --- |
| Id | int | PK, автоинкремент |
| Name | string | обязательно, уникально, до 100 символов |
| Description | string? | необязательно, до 500 символов |
| CreatedAt | DateTime | UTC, ставится сервером при создании |

### Position — должность

| Поле | Тип | Ограничения |
| --- | --- | --- |
| Id | int | PK, автоинкремент |
| Title | string | обязательно, уникально, до 100 символов |
| MinSalary | decimal | ≥ 0, нижняя граница зарплаты |
| MaxSalary | decimal | ≥ MinSalary, верхняя граница зарплаты |

### Employee — сотрудник

| Поле | Тип | Ограничения |
| --- | --- | --- |
| Id | int | PK, автоинкремент |
| FirstName | string | обязательно, до 100 символов |
| LastName | string | обязательно, до 100 символов |
| Email | string | обязательно, уникально, формат email |
| Phone | string? | необязательно, до 30 символов |
| HireDate | DateTime | дата приёма на работу, не позже сегодняшнего дня |
| Salary | decimal | ≥ 0, в границах зарплаты должности |
| IsActive | bool | по умолчанию true; false = уволен |
| DepartmentId | int | FK → Department.Id |
| PositionId | int | FK → Position.Id |

### LeaveRequest — заявка на отпуск

| Поле | Тип | Ограничения |
| --- | --- | --- |
| Id | int | PK, автоинкремент |
| EmployeeId | int | FK → Employee.Id |
| LeaveType | enum LeaveType | Vacation = 1, Sick = 2, Unpaid = 3 |
| StartDate | DateTime | начало отпуска |
| EndDate | DateTime | не раньше StartDate |
| Status | enum LeaveStatus | Pending = 1, Approved = 2, Rejected = 3; при создании Pending |
| Reason | string? | необязательно, до 500 символов |
| CreatedAt | DateTime | UTC, ставится сервером при создании |

Сотрудника не удаляют из базы: увольнение ставит IsActive = false.

## Технические требования

Все девять пунктов обязательны: без любого из них работа не принимается.

| Требование | Что должно быть в решении |
| --- | --- |
| Web API | ASP.NET Core Web API на контроллерах с `[ApiController]`; REST-маршруты `api/...`; коды ответов 200, 201, 204, 400, 404, 409, 500 по смыслу |
| Async | Все операции ввода-вывода асинхронные от контроллера до репозитория: `async/await`, суффикс `Async`, `CancellationToken` пробрасывается до Dapper через `CommandDefinition`. `.Result`, `.Wait()` и `Task.Run` вместо настоящего async запрещены |
| Dapper | Доступ к данным только через Dapper (`QueryAsync`, `QuerySingleOrDefaultAsync`, `ExecuteAsync`) и Npgsql; параметризованный SQL без склейки строк; минимум один запрос с JOIN и multi-mapping (`splitOn`). Entity Framework не используется |
| Clean Architecture | 4 проекта: Domain, Application, Infrastructure, Api. Зависимости направлены внутрь, Domain ни от кого не зависит; интерфейсы репозиториев — в Application, реализации — в Infrastructure |
| DTO | Контроллеры принимают и возвращают только DTO, сущности Domain наружу не выходят. Отдельные DTO для создания, обновления и ответа; валидация входных DTO (DataAnnotations или FluentValidation) |
| Swagger | Swagger UI на `/swagger`; `[ProducesResponseType]` на эндпоинтах; XML-комментарии минимум у 5 эндпоинтов. Для .NET 10 возьмите Swashbuckle.AspNetCore 10.x или `Microsoft.AspNetCore.OpenApi` + `Swashbuckle.AspNetCore.SwaggerUi`; не смешивайте два подхода в одном проекте |
| Логирование | `ILogger<T>` в сервисах и middleware. Information — ключевые операции (приём на работу, увольнение, решение по заявке), Warning — нарушение бизнес-правил, Error — необработанные исключения. Вывод в консоль обязателен |
| Middleware | Минимум 2 собственных: (1) глобальная обработка исключений — ответ `ProblemDetails` с правильным статус-кодом; (2) логирование запросов — метод, путь, статус ответа и время в мс. Регистрация в `Program.cs` в правильном порядке |
| Конфигурация и DI | Строка подключения в `appsettings.json`; регистрация сервисов через extension-методы `AddApplication()` и `AddInfrastructure()` |


## Обязательные эндпоинты API

Минимум 18 эндпоинтов. Полный CRUD обязателен для Departments и Employees; для Positions и LeaveRequests — только перечисленное ниже.

### Departments (5)

| Метод и путь | Что делает | Коды ответа |
| --- | --- | --- |
| GET /api/departments | список отделов | 200 |
| GET /api/departments/{id} | отдел по id | 200, 404 |
| POST /api/departments | создать отдел | 201, 400, 409 |
| PUT /api/departments/{id} | обновить отдел | 204, 400, 404, 409 |
| DELETE /api/departments/{id} | удалить отдел (если в нём нет сотрудников) | 204, 404, 409 |

### Positions (3)

| Метод и путь | Что делает | Коды ответа |
| --- | --- | --- |
| GET /api/positions | список должностей | 200 |
| GET /api/positions/{id} | должность по id | 200, 404 |
| POST /api/positions | создать должность | 201, 400, 409 |

### Employees (6)

| Метод и путь | Что делает | Коды ответа |
| --- | --- | --- |
| GET /api/employees?departmentId=&positionId=&search=&page=&pageSize= | список с фильтрами и пагинацией; в ответе названия отдела и должности (JOIN) | 200, 400 |
| GET /api/employees/{id} | карточка сотрудника с отделом и должностью (JOIN) | 200, 404 |
| POST /api/employees | принять на работу | 201, 400, 404, 409 |
| PUT /api/employees/{id} | обновить данные сотрудника | 204, 400, 404, 409 |
| POST /api/employees/{id}/terminate | уволить (IsActive = false) | 204, 404, 409 |
| GET /api/employees/{id}/leave-requests | заявки сотрудника | 200, 404 |

### LeaveRequests (4)

| Метод и путь | Что делает | Коды ответа |
| --- | --- | --- |
| POST /api/leave-requests | подать заявку (Status = Pending) | 201, 400, 404, 409 |
| GET /api/leave-requests?status= | список заявок с именем сотрудника (JOIN), фильтр по статусу | 200, 400 |
| POST /api/leave-requests/{id}/approve | согласовать заявку | 204, 404, 409 |
| POST /api/leave-requests/{id}/reject | отклонить заявку | 204, 404, 409 |

Список сотрудников возвращает обёртку `PagedResult<T>` с полями Items, Page, PageSize и TotalCount. Значения по умолчанию: page = 1, pageSize = 20, максимум pageSize = 100.

## Бизнес-правила

Правила реализуются в слое Application (сервисы), а не в контроллерах. Каждое нарушение должно давать указанный код ответа и понятное сообщение.

1. Email сотрудника уникален — иначе 409.
2. Название отдела и название должности уникальны — иначе 409.
3. Должность: MaxSalary не меньше MinSalary — иначе 400.
4. При приёме и обновлении сотрудника Salary должна лежать между MinSalary и MaxSalary его должности — иначе 400.
5. HireDate не может быть в будущем — иначе 400.
6. Сотрудника нельзя принять в несуществующий отдел или на несуществующую должность — 404.
7. Отдел с активными сотрудниками удалить нельзя — 409.
8. Уволенного сотрудника нельзя уволить повторно и нельзя подать заявку на отпуск за него — 409.
9. Заявка на отпуск: EndDate не раньше StartDate, StartDate не в прошлом — иначе 400.
10. Одна заявка типа Vacation — не больше 28 календарных дней — иначе 400.
11. Периоды заявок одного сотрудника со статусом Pending или Approved не могут пересекаться — иначе 409.
12. Согласовать или отклонить можно только заявку в статусе Pending — иначе 409.

### Соответствие ошибок и HTTP-кодов

Студент сам заводит исключения в Domain или Application; middleware обрабатывает их и возвращает `ProblemDetails`.

| Исключение | HTTP-код |
| --- | --- |
| NotFoundException | 404 |
| ConflictException | 409 |
| ValidationException | 400 |
| любое другое | 500, без stack trace в ответе |
